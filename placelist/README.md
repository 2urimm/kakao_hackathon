# 플레이스리스트 — 채팅 전 단계 MVP

카카오맵 즐겨찾기 폴더를 그대로 "리스트"로 쓰고, 그 위에 **리스트 온도, 친구 리스트, 지역·업종·상황별 랭킹, 사람 기반 추천**을 얹은 데모.
채팅(리스트 자동 추가 칩, 플리 봇)은 `Engine.search_places` 위에 얹는다.

## 화면

지도 + 왼쪽 패널 (모바일 폭에서는 아래 시트). 프론트는 React(Vite) — `frontend/`.

| 탭 | 내용 |
|---|---|
| 내 리스트 | 내 대표·업종별 온도, 내가 만든 리스트, 구독 중인 리스트 |
| 친구 | 친밀도 순으로 친구와 그 친구의 리스트 (온도 포함) |
| 궁합 | 내 리스트와 친구 리스트의 궁합 점수(0~100): 취향 50% + 겹치는 장소 20% + 활동 동네 15% + 가격대 15%. 카드를 누르면 공통 분위기·같이 저장한 곳·친구만 가본 곳이 지도에 ♥/★로 표시 |
| 랭킹 | 시상대(1~3위) + 목록. 리스트 / 큐레이터 × 지역 × 업종 × 상황(데이트·혼자·친구·가족·단체) 온도 랭킹 |
| 리스트 상세 | 리스트 온도와 "이 온도는 어떻게 나왔나요?" 근거, 장소별 메모·방문 인증·재방문·피드백, 구독하기 |
| 검색 | 자연어 → 메인 1곳 + 다른 축의 대안 2곳, 지도에 ★·2·3 핀 |

주소 해시로 바로 열 수 있다: `#friends`, `#ranking`, `#list=F02`, `#q=홍대 탈색 잘하는 곳` (발표 중 화면 전환용)

지도: `frontend/public/config.js`에 카카오맵 JavaScript 키를 넣으면 카카오맵 SDK, 비워 두면 Leaflet + OpenStreetMap 대체 지도.
(카카오 디벨로퍼스 > 내 애플리케이션 > 플랫폼 > Web에 데모 주소를 등록해야 키가 동작함.)
Leaflet은 npm 패키지로 번들에 포함되어 CDN 없이 동작한다 (지도 타일만 OpenStreetMap에서 받음).

## 프론트 (React + Vite)

```bash
cd frontend
npm install
npm run dev      # http://localhost:5173  (/api 는 python server.py :8000 으로 프록시)
npm run build    # ../web 에 정적 파일 생성 → python server.py 가 그대로 서비스 (http://localhost:8000)
```

`frontend/src`: `App.jsx`(상태·탭·예약 이벤트 폴링) · `views/`(Mine, Friends, Compat, Ranking, ListDetail, Search) · `Toasts.jsx` · `ui.jsx`(아이콘·온도·아바타·리스트 행) · `map.js`(카카오맵/Leaflet 어댑터) · `api.js`(`useApi`).
카카오맵 키는 `frontend/public/config.js`. 이전 순수 JS 화면은 `web_legacy/`에 남겨 뒀다 (서버는 `web/` 빌드 결과를 서비스).

## 데이터

실제 카카오맵 장소 80곳 (서울 마포 20, 서울 서초 20, 부산 40). 지역 태그는 8개: 마포·서초·원도심·동래·수영·남구·해운대·사하·기장.

| 카카오맵에서 온 값 | 규칙으로 뽑은 태그 | 시뮬레이션 값 |
|---|---|---|
| 이름·주소·카테고리, 메뉴·가격, 시설, 영업시간, 휴무, 웨이팅 글 | 업종(음식점/카페), 가격대(메뉴 가격 중앙값), 분위기, 목적, 대표메뉴, 음식종류, 적정인원, 웨이팅, 주차, 늦게까지 영업, 작업하기 좋음 | 큐레이터·리스트 구성(우슬랭가이드 폴더만 실제 이름·구독자 수), 메모 문장, 방문 인증, 재방문, 친밀도, 피드백 |

- 좌표는 주소(도로명)로 OSM에서 구해서 **건물 단위로는 부정확**하다. 못 찾은 곳(2곳)은 지역 중심 근처에 찍힌다. 카카오 REST 키가 있으면 `import_kakaomap.py`가 더 정확하다.
- 메모 문장은 장소의 메뉴·시설·영업시간 사실에서 만든 문장이다. 우슬랭가이드 앞 4곳만 실제 메모.
- 부산·마포·서초 큐레이터 이름과 폴더 제목(`부산 로컬 맛집 지도` 등)은 임시로 붙인 값이다.
- 미용 장소는 이 데이터에 없어서 화면에서 미용 필터가 사라진다.

## 예약 확정 연동 (채팅 백엔드 → 여기)

채팅 쪽 백엔드가 예약을 확정하면 이 서버로 한 번 호출한다.

```http
POST /api/reservation          (CORS 허용)
{"reservation_id": "R123", "user": "자갈치토박이", "place_id": "k1297139609" 또는 "place_name": "다무치아",
 "list_id": "B01",             // 선택: 어느 리스트를 보고 예약했는지. 없으면 팔로우 → 친구 → 온도 높은 순으로 고름
 "datetime": "2026-11-08 19:00", "party_size": 2, "status": "confirmed"}   // confirmed | pending | cancelled
```

- 같은 `reservation_id`가 또 오면 한 번만 반영 (멱등). `cancelled`는 온도를 되돌린다. `pending`은 알림만.
- 반영 방식: 예약 확정 = 방문 인증된 사람의 "좋았어요" 1건 (`placelist/reservations.py`). 기존 체감(1, 1/2, 1/3…)·사람당 상한 1.5·자기 리스트 무시 규칙이 그대로 적용된다.
- 화면(2초마다 `GET /api/events`): 오른쪽 위 알림("예약 확정 · 리스트 온도 44.4 → 45.1℃ · 동래 음식점 랭킹 4위 → 3위"), 리스트 온도 ▲ 표시와 숫자 올라가는 애니메이션, 랭킹 순위 ▲▼ 표시, 내 리스트 탭의 "내 예약". 알림을 누르면 그 리스트로 이동.
- 예약이 없을 때와 비교한 값(`temp_delta`, `rank_delta`)은 서버가 항상 계산하므로 새로고침해도 유지된다. 예약은 `data/build/reservations.json`에 저장.

시연용: `python scripts/send_reservation.py 동래빵지순례자 "스필아웃" --list F07` (마포 음식점 2위 → 1위),
`python scripts/send_reservation.py 동래빵지순례자 "동래밀면" --list F01` (동래 음식점 4위 → 3위),
`--cancel R0001`로 취소, `--reset`으로 예약 기록 삭제.

## 추천 점수

리스트에 담긴 장소 항목 하나의 점수:

$$S_{list} = w_C C + w_T T + w_R R + w_P P + w_D D + w_V V$$

- $C$ 맥락 일치도: 검색 조건(분위기, 목적, 가격, 웨이팅, 주차, 늦게까지, 작업, 상담 스타일) 중 맞은 비율. 태그나 큐레이터 메모에 근거가 있으면 맞은 것으로 본다. 조건이 없으면 1, 하나도 못 맞추면 후보에서 뺀다.
- $T$ 큐레이터 온도: 그 항목을 담은 큐레이터의 **해당 업종** 온도를 $\frac{온도 - 32}{46 - 32}$로 0~1로 바꾼 값
- $R$ 친밀도: 검색하는 사람과 큐레이터 사이 값(0~1). 모르는 사람이면 0
- $P$ 취향 유사도: 검색자 리스트에서 만든 태그 벡터와 장소 태그 벡터의 코사인 유사도. 검색자 리스트가 없으면 0.5
- $D$ 최신성: $e^{-\lambda \Delta t}$
  - $\Delta t$: 메모를 저장한 뒤 지난 일수
  - $\lambda = 0.01$: 약 70일 뒤 절반
- $V$ 방문·재방문: 방문 인증이면 $0.5 + 0.5 \cdot \frac{\min(재방문, 3)}{3}$, 인증이 없으면 0
- $w$: 가중치

| 업종 그룹 | $w_C$ | $w_T$ | $w_R$ | $w_P$ | $w_D$ | $w_V$ |
|---|---|---|---|---|---|---|
| 맛집 (음식점·카페) | .30 | .20 | .20 | .15 | .05 | .10 |
| 뷰티 (미용) | .25 | .20 | .15 | .10 | .05 | **.25** |

최종 점수 (카카오맵 태그 점수와 점진 블렌딩):

$$S = \alpha \, S_{list} + (1-\alpha) \, S_{tag} + B_{단계}, \qquad S_{tag} = 0.6C + 0.4P, \qquad \alpha = \min\left(1, \frac{n}{12}\right)$$

- $\alpha$: 리스트 반영 비율
- $n$: 그 지역 × 업종 그룹에 담긴 리스트 항목 수. 12개 이상이면 리스트만으로 판단
- $S_{tag}$: 큐레이터 없이 장소 태그만으로 낸 점수
- $B_{단계}$: 팔로우한 리스트 +0.08, 친구 리스트 +0.04, 그 외 0

### 범위 단계

팔로우한 리스트 → 친구(친밀도 > 0)의 리스트 → 온도 40℃ 이상 큐레이터의 공개 리스트 → 카카오맵 장소 태그.
서로 다른 장소가 3곳 모일 때까지만 넓힌다. 3단계에서 메인이 나오면 그 큐레이터 팔로우를 제안한다.
지역을 말하지 않으면 검색자의 주 활동 지역으로 찾고, 결과가 없으면 지역 조건을 푼다.

### 대안 2곳

점수 2·3위가 아니라 축으로 고른다: 더 저렴한 곳 → (미용) 상담 스타일이 다른 곳 → 역에서 더 가까운 곳 → 분위기가 다른 곳.
대안도 맥락 일치도 0.5 이상, 메인 점수의 60% 이상이어야 하고, "분위기가 다른 곳"이 아니면 요청한 분위기는 지켜야 한다.
미용은 장소가 모자라면 같은 미용실의 다른 디자이너를 보여준다.

## 온도

같은 식을 두 단위로 계산한다.
- **리스트 온도**: 리스트 하나에 담긴 항목과 그 리스트에 달린 피드백만으로 계산. 리스트 카드, 상세, 리스트 랭킹에 표시
- **큐레이터 × 업종 그룹 온도**: 그 사람이 담은 해당 업종 항목 전부로 계산. 프로필의 업종별 온도, 큐레이터 랭킹, 추천 점수의 $T$
- **대표 온도**: 업종 그룹 온도를 항목 수로 가중 평균

$$T = 36.5 + 3\ln(1+G) - 4\ln(1+B) + 0.6\ln(1+S) + 2r + 2(v - 0.5) - A - Z$$

($T$는 30~50℃로 자른다)

- $G$: "좋았어요" 합. 같은 사람이 준 $k$번째 피드백은 $\frac{w}{k}$만 반영하고, 한 사람당 합은 1.5까지 (지인 몰아주기 방지)
  - $w$: 피드백 준 사람이 방문 인증했으면 1, 아니면 0.3
- $B$: "별로였어요" 합. 계산 방식은 $G$와 같음
- $S$: 그 업종 항목이 담긴 리스트들의 구독자 수 (리스트 안에서 그 업종이 차지하는 비율만큼)
- $r$: 재방문 표시가 있는 항목 비율
- $v$: 방문 인증된 항목 비율
- $A$: 오래 방치 감점. 평균 저장 경과일이 90일을 넘으면 60일마다 1점, 최대 3점
- $Z$: 홍보성 패턴 감점 2.5점. 인증 비율이 30% 미만이면서 항목이 3개 이상이거나 같은 장소를 여러 리스트에 반복 등록한 경우

같은 큐레이터가 동일 장소를 여러 리스트에 반복 등록했는지($Z$)는 리스트 온도에서도 큐레이터 기준으로 본다.

### 랭킹

조건(지역·업종·상황)에 맞는 장소가 2곳 이상(리스트가 그보다 작으면 전부) 담긴 리스트를 리스트 온도 순으로 정렬한다.
큐레이터 랭킹은 조건에 맞는 장소를 담은 큐레이터를 해당 업종 그룹 온도 순으로 정렬한다.

샘플 데이터에서: 서연(뷰티) 49.1℃, 수진(뷰티) 46.1℃ … 현우(오래 방치) 37.0℃, 핫플봇(홍보성) 30.0℃.
하늘이 태현에게 "좋았어요"를 5번 몰아줬지만 상한 때문에 1.5까지만 반영된다.
